# UX-ревью MURF — фаза 1

Дата: 31 октября 2026. Ревью текущей Android-копии по исходникам; это не результат наблюдения за пользователями или проверки на устройстве. Исходное рабочее дерево было чистым. Сборка, Gradle, эмулятор и Android-тесты не запускались: SDK отсутствует, пользователь запретил попытку сборки. Коммиты, push и операции с remote не выполнялись.

## Вывод

Проблема не столько в количестве возможностей, сколько в отсутствии иерархии: список чатов одновременно служит каталогом повседневных действий, установщиков, интеграций и администрирования. Ещё три разных понятия названы «задачами», а «профиль» обозначает и конфигурацию агента, и подключение к телефону. Первая фаза уменьшает эту перегрузку без изменения протоколов, данных и логики подключения.

Ниже «до» означает состояние до правок этой фазы. «Предложение» описывает целевую архитектуру; она реализована только в явно перечисленной части.

## 1. Карта экранов и функций

Пути в таблицах относительно `android/app/src/main/java/com/uzairansar/hermex/`, если не указан другой корень. Это карта пользовательских экранов, вложенных состояний, меню и диалогов, а не список каждой декоративной Composable-функции.

### Навигационный граф

Единственный основной `NavHost`: [`ui/HermexApp.kt`](android/app/src/main/java/com/uzairansar/hermex/ui/HermexApp.kt). Старт после проверки восстановленного входа: `sessions` для авторизованного пользователя, иначе `onboarding`. Смена сервера возвращает к списку чатов; защищённые входящие переходы ожидают авторизации.

```text
MainActivity → HermexApp → проверка восстановленного входа
├─ onboarding → sessions / ожидающий deep link / импортированный черновик
│  ├─ deploy → sessions после установки и подключения
│  └─ dsh → локальный чат Harness / удалённый WebView
├─ sessions
│  ├─ chat/{sessionId} → workspace/{sessionId}, git/{sessionId}, screen
│  ├─ settings → sessions?showArchived=true / onboarding после выхода
│  ├─ screen, dsh, bots, devices, local, drive, deploy [главные ссылки ДО]
│  ├─ panels?section=tasks, kanban
│  └─ more → phone, providers, bottasks, clis,
│             panels?section=skills|memory|insights [ДО]
├─ bots → bot/{botId} → botchat/{chatId} → другой botchat/{chatId}
│  └─ clis / bottasks
├─ dsh → providers / devices / local / phone
├─ panels?section={section} → задачи / навыки / память / статистика
└─ kanban-lab?scenario={scenario} [только DEBUG]
```

### Главный экран, drawer, вкладки и нижние панели

- Отдельного основного `ModalNavigationDrawer` и постоянного `NavigationBar` здесь нет. «Sidebar» — сам `SessionListRoute`: на телефоне вертикальная страница, на широком экране — колонка слева. Не следует проектировать исправления исходя из несуществующей нижней навигации.
- В шапке: идентичность/аватар сервера, поиск и вход в настройки. Ниже до правок: **Экран, Harness, Боты, Устройства, Локальная среда, Google Диск, Свой VDS, Задачи, Канбан, Ещё**; в landscape ссылки раскладываются по две в ряд.
- Затем раскрываемые активный профиль и проекты: выбор профиля, фильтр проекта, создание, переименование, цвет и удаление проекта. Статус загрузки/кеша/ошибки, переподключение, сворачиваемые запуски по расписанию, список чатов, плавающая кнопка нового чата и голосовой сценарий.
- Действия над чатами: открытие, переименование, архивирование/восстановление, ветвление, удаление с подтверждением, копирование заголовка/ссылки, экспорт. См. `SessionRow`, `SessionSwipeContainer`, `SessionDialogs` в `SessionListRoute.kt`.
- Межэкранные свайпы — отдельная навигация: `sessions → screen → phone → drive → tasks → kanban → skills → memory → insights`, часть пунктов зависит от предпочтений. `mainSectionOrder`, `MainSectionSwipe` в `HermexApp.kt`; обработка жестов — `agent/UiPrefs.kt`. Этот порядок уже до правок отличался от видимого меню.
- В Harness есть настоящие вкладки «На телефоне» / «На Hermes» (после правки «На сервере»). В онбординге — горизонтальный pager. В чате нижний composer, в kanban/пикерах — sheets и локальные переключатели; это не глобальная нижняя навигация.

### Первый запуск: что действительно есть

- `OnboardingFlowPolicy`: приветствие → обзор функций → инструкция для настройки Hermes Web UI → Tailscale → подключение. Можно перейти сразу к подключению, а при сохранённом URL оно выбирается автоматически. Есть напоминание скопировать prompt, которое можно обойти.
- На подключении: URL, условно пароль, скрываемые custom headers, проверка/подключение, QR/ручной код/VDS; до правки ещё и форма API-ключа для локального Harness на той же странице. Ссылка «Агент на телефоне» доступна с предыдущих страниц.
- **Общего мастера выбора Harness/Grok/Hermes в этой копии нет.** Поиск по исходникам и `CHANGELOG.md` подтверждает отсутствие SelfServe wizard в навигации; тест `OnboardingAuthErrorPolicyTest` запрещает такой незавершённый пункт по умолчанию.
- Grok присутствует как `grok` backend бота (`MurfBots.kt`, `MurfBotsRoute.kt`) и как xAI-провайдер моделей (`MurfProviders.kt`); это не самостоятельный экран онбординга. Серверный запуск реализован в `server/phone-relay/murf_bots.py`.
- QR понимает Hermes pairing и Harness auth-ссылку, но Hermes chat API и удалённый Harness — разные способы работы. `OnboardingViewModel.kt` сообщает об этом; полноценного автоматического перехода в общий «универсальный чат» нет.

### Диагностика и внешние входы

- `agent/ProblemReport.kt`: категории ошибка/зависание/идея, описание, приложить журнал, preview, отправить на свой сервер либо скопировать; редактирование чувствительных значений делает report builder. Вход: Настройки → App.
- `agent/ServerUpdates.kt`: статусы компонентов, проверки/обновления и журналы. `agent/AppUpdates.kt`: проверка/диалог обновления приложения; вызывается и глобально из `HermexApp.kt`.
- `LocalRoute`: диагностика локальной среды/провайдера/сети/служб и журнал. `PhoneRoute`: мост/Termux/история запросов. `MurfClisRoute`: диагностика CLI. `VdsDeployRoute`: preflight и install log. Kanban: worker log, ошибки совместимости и диспетчера.
- `MainActivity.kt`, `ui/ShortcutDestination.kt`, `ui/HermexApp.kt`, `AndroidManifest.xml`: входящие `hermes-agent://sessions`, `new-chat`, `new-chat-voice`, `new-chat-profile`, `share`, `session?id=…`, `settings`, `panels`, профильные shortcuts. `ui/ProfileShortcutPublisher.kt` публикует shortcuts; `HermexWidgetProvider.kt` открывает список/новый/голосовой чат.
- `ShareActivity.kt` принимает `ACTION_SEND`/`ACTION_SEND_MULTIPLE`, сохраняет черновик и открывает сценарий выбора/создания чата; это вход в основной UI, не отдельный постоянный раздел.
- Debug-only `src/debug/.../visual/VisualFixtureActivity.kt` и `kanban-lab` — тестовые поверхности, не пользовательская диагностика production.

## 2. Проблемы и доказательства

## 3. Предлагаемая информационная архитектура

### Главный экран

Основная задача — продолжить или начать разговор. Шапка: название выбранного подключения, понятный статус, поиск, настройки. Ниже — недавние чаты и «Новый чат». Проекты и профиль — фильтры, раскрываемые по запросу. Быстрые ссылки: экран агента, боты, расписание, доска задач; установка/ключи/Termux/Drive не должны занимать первые строки.

Для фазы 1 оставлен существующий каркас с пятью ссылками перед списком вместо десяти. Перенос списка выше всех ссылок и новая постоянная навигация требуют проверки малых экранов, клавиатуры, планшета и жестов.

### Целевое дерево

```text
Чаты [главный]
├─ Новый чат / голос / входящий файл
├─ Недавние чаты → разговор
│  ├─ Экран агента
│  ├─ Файлы и Git
│  ├─ Задачи этого чата
│  └─ … → Экспорт и другие действия
├─ Поиск / Проекты / Профиль агента
└─ Быстрые ссылки: Боты · Расписание · Доска задач · Экран агента

Дополнительно
├─ Агенты и модели
│  ├─ Агент Harness → На телефоне / На сервере
│  ├─ Модели на телефоне
│  └─ Движки ботов (CLI)
├─ Задачи и знания
│  ├─ Расписание → задания и история запусков
│  ├─ Доска задач → карточки и диспетчер
│  ├─ Запуски ботов
│  ├─ Навыки
│  ├─ Память агента
│  └─ Статистика использования
├─ Подключения и устройства
│  ├─ Устройства (QR)
│  ├─ Google Диск
│  └─ Телефон и Termux
└─ Установка и обслуживание
   ├─ Среда на телефоне
   └─ Установить сервер

Настройки
├─ Подключения → Серверы / Активный сервер / Архив / Выход
├─ Модели и профили на сервере
├─ Внешний вид → тема / шрифт / цвета / иконка
├─ Чат и ввод → голос / отправка / оформление сообщений
├─ Уведомления и взаимодействие → уведомления / жесты / анимации
├─ Список чатов → фильтры и видимые быстрые ссылки
├─ Дополнительно → headers / кеш / системные настройки Android
└─ Помощь и диагностика → отчёт / журналы / обновления / о приложении
```

Повтор расписания и доски в «Дополнительно» допустим как полный каталог: главные ссылки — отключаемые ярлыки, а не отдельные экраны или дубликаты данных. «Профиль агента» — конфигурация поведения; «Подключение» — сервер или телефон. Термин «Grok» показывать в выборе движка/модели, а не как равнозначный способ подключения рядом с Hermes.

### Первый запуск

Предлагаемый первый вопрос: «Где будет работать агент?» с вариантами «Подключить готовый сервер» и «На этом телефоне», плюс «Установить сервер» в дополнительных вариантах. Для готового сервера сначала QR/код или адрес, затем только необходимые для выбранного метода поля. Инструкцию Tailscale открывать как помощь по настройке, а не обязательную экскурсию для всех.

Для телефона: проверить Termux/среду → установить при необходимости → выбрать провайдера и модель → начать чат. Технические подробности, журналы, свои API URL и расширенные параметры раскрываются по запросу. Для удалённого Harness — явная подпись «Подключение к Harness», собственная ссылка/код и свой клиент. Не превращать разные протоколы в один переключатель, пока не определены capability/error/deep-link сценарии.

В фазе 1 изменена только видимость необязательной формы моделей телефона на странице Hermes; последовательность, проверки, QR, пароли, сохранённые данные и напоминание о prompt сохранены.

### Пустые состояния

| Контекст | Сообщение и следующий шаг |
|---|---|
| Нет чатов | «Чатов пока нет» → существующая кнопка нового чата. |
| Пустой поиск/фильтр | «Чаты не найдены» → изменить запрос/проект/фильтры. Отдельно «Ищем чаты…», пока поиск не завершён. |
| Нет кешированных результатов/ошибка | Не обещать, что чатов нет на сервере; проверить сеть и обновить. |
| Архив | «Архив пуст» → объяснить, что сюда попадают архивированные чаты. |
| Запуски cron | «Запусков по расписанию пока нет» → создать расписание и дождаться запуска. |
| Провайдеры телефона | «Модели ещё не настроены» → добавить провайдера, ключ и выбрать модель. Пустой каталог моделей → обновить/проверить ключ. |
| Боты | Сохранить существующее предложение создать первого; объяснить выбор движка после имени и назначения бота. |
| Harness | Предложение нового чата только после успешной загрузки пустого списка; отдельно loading/ошибка/нет входа. Пока отложено. |
| Нет подключения | Общий recovery-компонент «Подключите сервер» с действием; не молча пустая Composable. Пока отложено. |

## 6. Что осталось и почему

- Полный мастер первого запуска, общая модель выбора агента, capability-based навигация и recovery auth: зависят от разных протоколов и требуют интеграционных проверок, а не только перестановки UI.
- Общая нижняя панель, чаты выше ярлыков, полное разделение Settings: это изменение каркаса и адаптивной компоновки; без проверки узких/широких экранов риск выше разумного для этой фазы.
- Свайпы и три старых переключателя Main Page (навыки/память/статистика) всё ещё требуют согласования. Они не удалены и сохраняют прежнее влияние на свайпы.
- Чат, его экспорт и инструменты не перепакованы: это большой экран с потоковыми и permission-состояниями. Функции перечислены в карте и остаются доступны.
- Harness пока не получил отдельное «пусто/загрузка/ошибка списка»: сейчас состояние сессий начинается с `emptyList`, а неуспешный fetch не даёт отдельной модели ошибки. Одной надписью это честно не исправить.
- RU/EN уточнены в основных входах; полный словарь всех подсказок и локалей не мигрирован. Названия в настройках и контекстных текстах местами ещё старые. Существующие локализованные ресурсы не удалены.
- Необязательная форма моделей раскрывается отдельной кнопкой; после открытия используется её собственное управление сворачиванием, чтобы не удалять форму и её coroutine scope внешним переключателем. Перед релизом проверить работу формы во время запроса и поворот устройства.

Перед включением в релиз: на машине с SDK запустить добавленные/обновлённые unit/UI-тесты; вручную пройти RU/EN, большой шрифт, узкий экран и планшет, все группы «Дополнительно» и Back, отключённые ярлыки задач/доски, вход Hermes/QR/Harness, пустой архив, поиск в процессе, offline-кеш и раскрытие настроек. Здесь эти проверки не подменяются заявлением «всё работает».
